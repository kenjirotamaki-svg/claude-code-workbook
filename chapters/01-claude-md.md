# 第1章 CLAUDE.md — 毎回読み込まれる個人ルール

## 1. この章のゴール

CLAUDE.md を書いて、Claude の返答の仕方を自分好みに変えられる。

## 2. しくみ

```text
セッション開始
   │
   ▼
Claude Code が CLAUDE.md を読み込む
   │  中身を、Claude への指示として会話の最初に入れる
   ▼
Claude: 会話のあいだずっと、その指示を踏まえて答える
```

| 項目 | 内容 |
|---|---|
| 読み込まれるとき | セッション開始時（毎回） |
| 置き場所 | プロジェクトのルートの `CLAUDE.md`（そのプロジェクトだけ）、`~/.claude/CLAUDE.md`（すべてのプロジェクト。第7章） |
| トークンへの影響 | 毎回読み込まれるので、**長いほど毎回のトークンが増える**。短く保つ |
| 強さ | **お願い**。Claude が読んで従うもので、守られないこともある |

**何を書くか**: どんな作業でも守ってほしいことだけを書く。特定のファイルだけのルールは第2章の rules に、決まった手順は第3章の skills に分ける。

出典: https://code.claude.com/docs/en/memory

## 3. 作ってみる

作るもの: `~/claude-practice/CLAUDE.md`（練習用フォルダの直下に置く）

1. 練習用フォルダの直下に `CLAUDE.md` を作り（`~/claude-practice/CLAUDE.md`）、次の内容を書く（完成例: [examples/01-claude-md/CLAUDE.md](../examples/01-claude-md/CLAUDE.md)）。

```markdown
# 個人ルール

## About me
- <名前>。<職種>、経験<年数>年（<得意な技術>）。
- <慣れていない分野> は初心者なので、その分野の解説は用語を説明しながら順を追って説明する。

## 答え方
- 最初に要約（1〜3行）、そのあとに詳細を書く。

## 先に確認すること
- 新しいファイルやフォルダを作る前に、パスと理由を1行で伝えて確認を取る。
```

2. `<...>` を自分の情報に書き換える。

```markdown
## About me
- 山田。バックエンドエンジニア、経験3年（Python・FastAPI）。
- インフラ（AWS）は初心者なので、用語を説明しながら順を追って説明する。
```

3. 保存したら、Claude Code で**新しいセッション**を開く（CLAUDE.md はセッション開始時に読み込まれるため）。

## 4. 試してみる

| # | やること | 成功したときの結果 |
|---|---|---|
| 1 | `/context` を入力する | Memory files に `~/claude-practice/CLAUDE.md` が出ている（`~/.claude/CLAUDE.md` など、ほかの場所の CLAUDE.md が一緒に出ていてもよい） |
| 2 | 「HTTP と HTTPS の違いは？」と聞く | 最初に 1〜3 行の要約があり、そのあとに詳細が続く |
| 3 | 「<慣れていない分野> の〇〇とは？」と聞く（例:「AWS の VPC とは？」） | 用語の説明から、順を追って答える |
| 4 | 「hello.txt を作って」と頼む | ファイルを作る前に、チャットで「hello.txt を作成します。よろしいですか？」のように確認してくる |

**比べてみる**: `~/claude-practice/CLAUDE.md` の名前を `_CLAUDE.md` に変えて（読み込まれなくなる）、新しいセッションで 2〜4 を聞き直す。返答の形が変わることを確かめたら、名前を `CLAUDE.md` に戻す。

> 💡 `~/.claude/CLAUDE.md` にすでに自分のルールがある人は、その影響も混ざる。たとえば、そちらにも「要約から答える」と書いてあれば、名前を変えても返答の形は変わらない。

> 💡 4 の確認は、Claude が CLAUDE.md を読んで**チャットで聞いてくる**もの（お願い）。Claude Code の設定によっては、別に「このファイルを作成しますか？」という**確認ダイアログ**が出ることもある。こちらは Claude Code（プログラム）が出すもので、第5章・第6章で扱う「強制」の仕組み。

## 5. よくある疑問

<details>
<summary>Q. CLAUDE.md は何行くらいまで書いていい？</summary>

公式ドキュメントでは、1 ファイル **200 行以下**を目安にしている。長くなると、毎回のトークンが増えるうえに、指示が守られにくくなる。特定のファイルだけのルールは rules（第2章）に、手順は skills（第3章）に分けると短く保てる。

出典: https://code.claude.com/docs/en/memory
</details>

<details>
<summary>Q. プロジェクトの CLAUDE.md と ~/.claude/CLAUDE.md の内容が矛盾したら？</summary>

両方とも読み込まれる。矛盾している場合、Claude がどちらに従うかは決まっていない。自分の `~/.claude/CLAUDE.md` に「プロジェクトの CLAUDE.md と矛盾したら、プロジェクトを優先する」と書いておくと迷わない。
</details>

<details>
<summary>Q. 書いたのに守られないことがある</summary>

CLAUDE.md は「お願い」なので、守られないことはある。対策は次のとおり。

- 具体的に短く書く（「いい感じに」ではなく「最初に 1〜3 行の要約」）。
- 矛盾する指示がないか見直す。
- 絶対に守らせたいこと（例: `git push` させない）は、第5章の permissions や第6章の hooks で**強制**する。
</details>

<details>
<summary>Q. CLAUDE.md を書き換えたのに反映されない</summary>

CLAUDE.md はセッション開始時に読み込まれる。書き換えたら新しいセッションを開いて、`/context` で読み込まれているかを確認する。
</details>

## 6. 自分用に変える

自分がふだん Claude に毎回お願いしていることを 1 つ、CLAUDE.md に足してみる。

例:

- 「コードのコメントは日本語で書く」
- 「既存のコードを変更したら、最後に変更したファイルと行を一覧にする」
- 「推測で答えず、わからないことは『わからない』と言う」

足したら新しいセッションで試し、効いているかを確かめる。

## 7. 確認問題

<details>
<summary>Q1. CLAUDE.md が読み込まれるのはいつ？</summary>

セッション開始時（毎回）。だから書き換えたら新しいセッションで確認する。
</details>

<details>
<summary>Q2. CLAUDE.md に何でも書かず、短く保つべきなのはなぜ？</summary>

毎回読み込まれるので、長いほど毎回のトークンが増える。さらに、長くなるほど指示が守られにくくなる。
</details>

<details>
<summary>Q3. 「絶対に git push させたくない」。CLAUDE.md に書くだけで十分？</summary>

十分ではない。CLAUDE.md は「お願い」なので、守られないことがある。確実に止めたいことは、第5章の permissions（deny）で強制する。
</details>
